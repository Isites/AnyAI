# Core Page Quality

核心页面的内容价值来自“帮助真实用户完成目的”，不是文章长度本身。该目的可以是阅读内容、理解服务、完成业务流程、使用交互功能、比较方案或联系站点方。

## 高价值核心页面结构

核心业务、内容、产品、服务或交互页面建议包含：

- 核心主体：主要内容、服务说明、业务流程或交互功能可用。
- 简短定位：这个页面解决什么具体用户问题。
- 示例：至少一个真实输入和输出。
- 边界：适用范围、限制、失败原因、例外情况。
- 隐私：用户输入、表单、文件或行为数据如何处理，是否上传，第三方脚本是否参与。
- 工作流：真实用户如何在工作中使用它。
- 排错：常见错误和修复。
- 关联页面：自然连接到下一步内容、服务、功能或信任页面。

## 弱核心页面信号

- 只有 UI、列表、表单或按钮，缺少解释性内容。
- 每页都是同一组 FAQ。
- Use cases 只是泛泛写 developers、students、marketers。
- 没有示例数据。
- 没有错误状态说明。
- 没有说明页面如何处理用户输入、表单、文件或交易信息。
- 帮助/说明页与主页面重复。

## 内容模块建议

不同页面类型应该有不同内容重点：

- 内容/资讯页：来源、作者或站点责任、事实依据、更新时间、延伸阅读。
- 产品/服务页：适用对象、交付范围、限制、价格或联系方式、真实案例。
- 交互功能页：输入输出示例、错误状态、边界条件、隐私处理、下一步操作。
- 资源/下载页：文件来源、版本、使用限制、安全说明、替代路径。
- 对比/专题页：比较维度、取舍、证据、避免只替换关键词。

## 多语言要求

- 重要语言页应有等价内容价值。
- 不要只翻译标题和 FAQ。
- 如果无法维护某语言质量，可以先 noindex 或减少该语言索引面。

## 验收指标

这些是内部启发式：

- 核心页面有独特模块，不只是模板组件。
- sitemap 中的索引页都有清楚任务价值。
- 同一模板文本在大量页面上的占比受控。
- 用户不需要离开页面就能理解该页面的价值、限制和下一步行动。
